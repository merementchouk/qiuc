# AGENTS.md — QIUC Group Website Maintenance & Development Guide

This repository contains the source code for the **Quantum-inspired unconventional computing (QIUC)** research group website hosted on GitHub Pages (`https://merementchouk.github.io/qiuc/`).

This document serves as the primary instructions for AI assistants, maintainers, and developers interacting with this repository.

---

## 1. System Architecture & Tech Stack

* **Content Source:** Written in Emacs Org-mode within the `org/` directory.
* **Export Engine:** Org files are exported to GitHub-Flavored Markdown via `ox-gfm`.
* **Static Site Generator:** Jekyll (running on GitHub Pages with the `tactile` theme).
* **Mathematics:** LaTeX equations embedded in Org are pre-rendered into `ltximg/` images or rendered via standard MathJax/Liquid layout hooks.

---

## 2. Directory Layout & Boundaries

```text
.
├── _config.yml         # Jekyll configuration (Collections, Theme, Plugins)
├── AGENTS.md           # Instructions and repository context for AI/human maintainers
├── README.md           # Setup, prerequisites (Arch Linux), and authoring workflows
├── org/                # PRIMARY SOURCE: Emacs Org files (.org)
│   ├── ltximg/         # Pre-rendered LaTeX images generated by Emacs for preview (internal)
│   └── topics/         # Sub-topic source files
├── topics/             # Exported Markdown files (.md) from org/topics/
├── _posts/             # Jekyll blog posts (might stay empty)
├── _layouts/           # Jekyll Liquid HTML layout templates (e.g., default, post, meeting)
├── _includes/          # Reusable HTML snippets (headers, nav, footers, mathjax)
└── assets/             # Static web assets, manually controlled
    ├── css/            # Custom CSS overrides
    └── meetings/       # Images, PDFs, and media linked across meeting recaps
```

### Agent Exclusion & Ignored Files

Refer to `.gitignore` for paths excluded from tracking and reading. AI agents **must NOT parse or modify**:
* `_site/`, `.jekyll-cache/`, `.jekyll-metadata` (Jekyll build artifacts)
* `vendor/`, `.bundle/`, `Gemfile.lock` (Environment dependencies)
* Emacs backup/auto-save files (`*~`, `#*#`, `.#*`, `ltximg/`)
* DrawIO temp files (`.$*`)

## 3. Workflow & Authoring Rules

### Source of Truth
1. **Org Files First:** All primary narrative text, formulas, and meeting notes originate in `org/`.
2. **Do Not Edit Exported Markdown Directly:** Edits to files under `topics/` or `_posts/` that originated from `.org` sources will be overwritten during the next Emacs `ox-gfm` export.
3. **Layouts & Jekyll Config:** Agent tasks dealing with site structure, CSS, collection pagination, or Liquid logic occur directly in `_layouts/`, `_includes/`, `_config.yml`, and `assets/`.

### Meeting Notes & Collections
* Meeting recaps live in `_posts/` or a custom collection (e.g., `_meetings/`).
* Front matter for meeting notes must include:
  ```yaml
  ---
  layout: meeting
  title: "Meeting Title / Recap"
  date: YYYY-MM-DD
  categories: [recaps]
  ---
  ```

## 4. Maintenance & Navigation Rules

When tasked with expanding site functionality or navigation:

1. **Maintain Static & Standard Liquid Compatibility:** 
   Use standard Jekyll objects, such as `page.previous`, `page.next`, 
`site.posts`, `site.collections`, rather than custom JavaScript or 
external build plugins to ensure zero-breakage deployments on GitHub Pages.
2. **Preserve Front-End Simplicity:**
   Theme customization must remain minimal and non-obtrusive, staying consistent with Jekyll's `tactile` base styling.
3. **Relative URL Filter:**
   Always run internal links through the `relative_url` filter in Liquid layouts:
   `{{ page.previous.url | relative_url }}`

---

## 5. Local Testing & Verification Commands

To test site structural changes or Liquid updates locally:

* **Install Dependencies:**
  ```bash
  bundle install
  ```
* **Serve Site Locally:**
  ```bash
  bundle exec jekyll serve --incremental
  ```
* **Verify Built Output:** If necessary, inspect `_site/` locally to ensure Liquid templates render valid, cross-linked HTML without breaking paths.
